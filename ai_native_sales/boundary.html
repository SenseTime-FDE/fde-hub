Human Checkpoints · Where The System Must Stop

自主，不等于失控 —— 四类节点，系统必须停下来找人

系统端到端自己跑，但它清楚地知道什么时候必须停：谁出面、谁担责、什么时候问、什么时候报，规则写得出来、边界配得出来、每一次都留了痕。说不出「什么时候找人」的自主，才叫失控。

01

四类必须找人的节点：为什么必须是人

反过来读更重要 —— 这四类写清楚了，「什么时候不找人」也就写清楚了

🤝
NODE 01要人脸出面

为什么必须是人关系与信任无法委托 —— 客户要见的是能拍板、能负责的人，不是一段生成的话术。

典型场景首访关键谈判高层拜访
怎么触发：主 Agent 把「见面」排进推进计划时，直接调度人出场，并把背调、纪要、谈判要点提前备好 —— 人到场即开谈。
金桥单出现 3 次：D5 首访 · D21 二访 · D27 商务谈判
✍️
NODE 02要人担责

为什么必须是人法律与商业责任必须落到自然人 —— 系统可以把账算清楚，但不能替人签字。

典型场景报价定案合同签署对外承诺
怎么触发：动作命中授权清单即转授权人，附判断、依据与建议动作 —— 留给人的是拍板，不是分析。
金桥单出现 3 次：D14 报价定案 · D34 账期授权 · D41 法务复核
🤔
NODE 03AI 没把握

为什么必须是人置信度低于阈值时，宁可停下来问，也不硬着头皮猜 —— 猜错的代价由商机承担。

典型场景客户意图模糊信息互相冲突没见过的场景
怎么触发：判断置信度低于企业设定阈值，立即停止自主执行，转人工并附上它纠结的几种解读。
完整示例见本页 05：置信度 61%，低于阈值 75%
📉
NODE 04结果偏离

为什么必须是人实际与预期偏差超过阈值，说明既有打法失效 —— 换方向这件事，该由人来定。

典型场景停滞超期赢率骤降客户降温
怎么触发：主 Agent 本来就在盯，偏差命中阈值即生成判断与建议，进待决队列 —— 不靠人报，也瞒不住。
金桥单：停滞 14 天（D21 异议起算）由主 Agent 自动发现并进队列
02

这四类之外，系统不找人

这是 L3 与 L2 的分水岭 —— 差别不在模型能力，在「谁被拴在流程上」

L2 · 代办工具的干法

每一步都要人点确认

自主完成率典型区间 20–40%（目标态示意 · 非承诺值）

同一条链路：二访结束 → 客户收到纪要 → 推进下一步
  1. 1人发起转写，系统出纪要草稿⏸ 等人确认
  2. 2系统起草外部版纪要⏸ 等人确认
  3. 3外发给客户⏸ 等人点发送
  4. 4下一步做什么人自己想、自己发起
系统每走一步，人就要出现一次 —— 人还是被拴在流程上，只是打字变成了点确认。
L3 · 条件自主（本方案）

只在四类节点出场

自主完成率典型区间 60–80%（目标态示意 · 非承诺值）

同一条链路，系统一口气跑完
  1. 1转写、分角色、抽取需求与异议✓ 自主 · 留痕
  2. 2生成外部版纪要，比对边界配置：内容类型在「可自主外发」清单内✓ 自主 · 留痕
  3. 3发出，并更新推进计划、排好下一步✓ 自主 · 留痕
  4. 4若下一步是账期让步 —— 命中「要人担责」停 · 进待决队列
未命中四类节点，全程不打扰任何人；命中了，停下来，把判断和依据一起端给人。

03

边界是配置出来的，不是写死的

「哪些事系统可以自己做」由企业说了算 —— 每一项可开关、可设值，收放自如

报价定案、合同签署、对外承诺，一律由授权人确认 —— 这一档锁死，不可配置为「自主」。

为什么边界必须可配置

🏢
每家企业的授权制度不一样折扣权限在谁手里、多大金额要走审批 —— 系统对齐的是企业既有的授权制度，不是反过来。
📈
爬坡过程中逐步放宽第 2 周从代办起步、逐件确认；第 3–4 周四类节点之外开始自主执行；第 2–3 月进入条件自主 —— 边界随信任一起放开。
↩️
随时可以收回来任何一项都能收紧或关闭，交出去的执行权每一步可回退 ——「上 AI」从一次性豪赌变成可控的爬坡。
配置本身也是受管对象：谁改的、什么时候改的、从什么值改到什么值，全部留痕，随时可查。
红线 · 不可配置

涉及法律与商业责任的动作 —— 报价定案、合同签署、对外承诺 —— 必须由授权人确认。这一条不随任何配置放开，也不随自主度爬坡放开。
