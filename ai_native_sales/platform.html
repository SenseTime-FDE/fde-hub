Agent Platform · 自主度的承重结构

让一支 Agent 团队能长期跑下去的那一层

没有它，自主度只能停在演示里。演示里让 Agent 端到端跑一遍不难；难的是它每天自己跑、跑错了能只回退错的那一段、跑了什么花了多少都算得清、企业还敢把真实客户数据和一部分执行权交给它。这一层就是为这四件事存在的 —— 接入、模型、编排、治理、观测。

一句话

L2 的工具可以没有平台，因为每一步都有人点确认，人就是兜底；L3 必须有平台，因为人不在场的时候，得有一层东西替它兜底。

01

平台五层架构

接入 · 模型 · 编排 · 治理 · 观测 —— 每一层都对应一个「缺了它，自主度就掉回 L2」的问题

接入层ACCESS

职责：信号从这里进来，动作从这里出去。商机主 Agent 要盯的四类信号 —— 客户动作、竞品动向、内部进度、时间流逝 —— 在这一层统一订阅；Agent 自主执行产生的结果再从这一层回写 CRM、推到企业微信与移动端、送进待决队列。不替代 CRM，过程与结果回写 CRM，不搬家不重建。

四类信号订阅动作回写 CRM待决队列出口企业微信 / 移动端触达Open API
没有它会怎样系统只能等人打开、等人输入。人不动，商机就不动 —— 自主完成率天然是 0，再强的模型也只是个搜索框。
模型层MODELS

职责：把能力接进来，并且随时能换掉。语言模型、语音与声纹模型、企业已有的私有化推理服务与第三方 Agent，用 OpenAI 兼容协议填地址即纳管；同一任务允许多方案并跑，按赢单贡献、成功率、人工纠偏率与成本自动择优。交付的是效果，不是型号清单。

语言模型（按效果择优）语音与声纹模型企业私有化模型兼容协议纳管第三方 Agent多方案并跑择优
没有它会怎样能力被锁死在某一个供应商的某一个版本上：效果退步换不掉、成本上涨躲不开，企业已有的私有化推理服务也白投。
编排层ORCHESTRATION

职责：让一支 Agent 团队像团队一样干活。主 Agent 规划分发，子 Agent 并行执行，评审 Agent 质检；不通过时不整条重跑，而是按「精准修改指令」只回退出错的那一个子 Agent。双模式并存：开放型任务走自主规划，强合规链路走流程编排的固定画布。

主 Agent 规划分发子 Agent 并行评审精准回退自主规划 / 流程编排双模式单节点重试 3 次超时熔断
没有它会怎样一个环节出错整条链路作废，也没人知道该重跑哪一段。人得守在旁边看着 —— 那就退回到 L2 的「逐个发起、逐个确认」。
治理层GOVERNANCE

职责：先划边界，才敢放权。四类必须找人的节点、各自的阈值与授权范围在这一层由企业配置；三角色分权、逐 Agent 最小授权、敏感字段脱敏；涉及法律与商业责任的动作（报价定案、合同签署、对外承诺）强制由授权人确认。每一次自主执行与每一次找人都留痕可审计。

四类节点与阈值配置三角色分权逐 Agent 最小授权敏感字段脱敏强制人工确认清单
没有它会怎样企业不敢把执行权交出去，只能靠「每一步点一下确认」找安全感 —— 于是永远停在 L2，人始终被拴在流程上。
观测层OBSERVABILITY

职责：自主度必须能被度量，否则不成立。按 Agent 统计调用量、耗时与成本；每一次运行可逐步回放（含评审回退）；自主完成率、人工纠偏率、建议采纳率与单位成本汇成能力记分卡，连续不达标的 Agent 下架换掉。看板也在这一层 —— 降级为审计与追溯入口。

按 Agent 调用量 / 耗时 / 成本运行 Trace 逐步回放全链路埋点能力记分卡审计日志
没有它会怎样答不出「上个月自主完成了多少动作、人纠偏了多少次」。按自评三问，答不出就等于没有自主度 —— 续不续用只能靠感觉。
底座

以商机为中心的统一数据对象：客户、关键人、商机、里程碑、拜访记录、纪要、知识条目、标讯、合同、回款节点、留痕事件 —— 一支 Agent 团队共用同一份商机上下文，不做第二份主数据。上下文不统一，主 Agent 就没法「盯」，也没法「判」。

合规口径：自主执行的边界、阈值与授权范围由企业配置；每一次自主执行与每一次找人都留痕可审计。五层能力均支持本地化部署，敏感字段自动脱敏、数据不出内网。

双模式调度：强合规链路（合同条款比对、投标合规自检、对外内容发出前）走流程编排的固定画布，可视化可核查；开放型任务走自主规划，主 Agent 按目标动态拆解。所有节点带重试与超时熔断，异常自动降级并留痕；每一步的输入、输出、耗时与成本全链路埋点，可在观测层逐步回放。这条链路里人只出现一次 —— 在最后，因为账期授权要人担责。

按 Agent 下钻的三个维度

调用量这个 Agent 被主 Agent 派了多少活。派得少，说明它在这个业务里没被真正用起来；派得多但纠偏率高，说明该换掉。
耗时「信号到动作时延」的分母就在这里。哪个节点在拖，逐 Agent 一眼看到，而不是笼统地说系统慢。
成本能力记分卡的成本项。同一任务多方案并跑时，效果与成本一起比，才叫按效果择优。

观测不等于监控个人：大盘按 Agent 与链路统计，用于容量、成本与质量运营；过程数据用于赋能与组织沉淀，不用于监控个人，采集、保存与查看范围由企业规则配置。

05

私有化与安全：先划边界，才敢放权

企业交出去的不只是数据，还有一部分执行权 —— 这四件事是交权的前置条件

⛁
数据不出内网支持本地化部署与企业已有的私有化推理服务，全链路在内网闭环，模型调用不留存客户业务数据。
⊘
敏感字段脱敏客户名称、金额、联系方式等按企业规则自动脱敏后再进模型；脱敏规则可逐字段配置。
▣
逐 Agent 最小授权每个 Agent 独立的模型、知识库与插件权限，互相隔离、按需开通；越权调用与越权提问直接拦截。
☷
三角色分权管理员 / 运维 / 业务三类角色分权，控制台每一个操作都进审计日志，改了什么、谁改的、什么时候改的可追。

合规口径：涉及法律与商业责任的动作（报价定案、合同签署、对外承诺）必须由授权人确认，平台不允许被配置为自主执行；录音需提前告知参会方，录音原文默认仅销售本人可见；过程数据用于赋能与组织沉淀，不用于监控个人。

部署三模式

按企业 IT 现状选，三种模式能力同源 —— 换的是部署形态，不是自主度上限

A
本地化部署数据全内网 · 适配企业已有的私有化推理服务 · 零第三方依赖
或
B
云端部署快速开通 · 先在一个团队试点，跑通再扩量
或
C
对接企业现有系统CRM、OA、企业微信渐进接入 · 不推翻现有流程，过程与结果回写

底座与第一批能力同期上线：自主度是逐步交出去的，但承接自主度的这一层必须一开始就在 —— 观察期只读不写的那一周，接入、治理与观测三层就已经在跑，否则第 2 周之后没有东西可以对表。落地节奏见 落地路线 →
