业务逻辑：事情怎么流转

  1. 01

    业务与待办进来

    xBuddies 的业务和飞书、钉钉的待办，一次录入，谁主责谁是主数据。

  2. 02

    Agent 团队承接

    专家智能体与岗位助理读同一套知识库与 Memory，出草稿，真人确认。

  3. 03

    模型统一接入与计量

    调用经 API 网关路由到 SenseNova、开源或第三方模型，按 Token Plan 计量。

  4. 04

    算力按需补充

    私有化部署利用客户已有算力；不足时租赁商汤算力，或接入云端 MaaS。

03业务闭环·HOW IT FLOWS

一条业务线，怎样贯通各层

以「一个商机从拜访到交付」为例（流程示意）：数据一次录入、全程复用，经验回流后下一轮更准。

  1. 01SalesBuddy

    拜访留痕

    • 语音或文件录入沟通过程
    • AI 整理并关联客户与商机
    • 缺失项保留「待确认」

    产出：客户 · 商机 · 跟进记录

  2. 02SalesBuddy

    判断与推进

    • 专家智能体识别商机卡点
    • 建议写到动作层面
    • 业务人员作最终判断

    产出：下一步行动与任务

  3. 03ProjectBuddy

    售前与立项

    • 销售发起售前任务
    • ProjectBuddy 承接，记录工时
    • 确认后回写跟进记录

    产出：售前记录 · 立项卡

  4. 04ProjectBuddy

    交付与验收

    • 六个关口逐关签字
    • 任务卡与验收证据留痕
    • 沉淀可复用的标准件

    产出：验收证据 · 标准件

  5. 05Raccoon X

    复盘与回流

    • 周报自动汇聚，反馈留痕
    • 经验与标准件进知识库
    • 下一次拜访与交付直接调用

    产出：知识与记忆更新

全程底座

每一步的模型调用经 API 网关 路由到 SenseNova 或第三方模型，按 Token Plan 计量到人。

一句话

数据一次录入，全链路复用：销售的记录是交付的输入，交付的结果是下一次销售的依据。

04部署形态·DEPLOYMENT

私有化、云端 SaaS、混合

同一套小浣熊企服版，按数据边界与已有算力选择。

看部署与落地陪跑

私有化部署

小浣熊企服版整套部署在客户本地，可利用客户已有算力。

适合：数据边界明确的金融、政企、国央企

云端 SaaS 多租户

开通即用，按智能体与 Token / Token Plan 使用；国内、海外两个平台。

适合：希望轻量起步、快速验证的企业

混合部署

本地 ＋ 云端：本地算力不足的部分，租赁商汤算力或用云端。

适合：已有算力的企业、集团型企业
